# Описание кода в части `timeout`

## Что делает код

Программа демонстрирует **ограничение времени выполнения асинхронной операции** с помощью `tokio::time::timeout`. Функция `fetch_data` имитирует долгую работу (10 мс), а `timeout` даёт ей только 5 мс. В итоге операция не успевает завершиться, и срабатывает ветка ошибки.

## Разбор `timeout`

### Сигнатура

```rust
pub async fn timeout<F>(duration: Duration, future: F) -> Result<F::Output, Elapsed>
where
    F: Future,
```

`timeout` принимает два аргумента :

- **`duration`** — максимальное время ожидания;
- **`future`** — асинхронная операция, которую нужно ограничить по времени.

Возвращает `Result`:

- **`Ok(value)`** — future завершился **до** истечения времени;
- **`Err(Elapsed)`** — время вышло, future был **отменён** (drop'нут).

### Использование в примере

```rust
match timeout(
    Duration::from_millis(5),   // лимит: 5 мс
    fetch_data()                // future, который нужно ограничить
).await {
    Ok(res) => {
        println!("Result: {res}");   // успели
    },
    Err(err) => {
        eprintln!("Error: {err}");   // не успели
    },
}
```

Здесь `timeout` возвращает `Result<u64, Elapsed>`:

- если `fetch_data()` успеет за 5 мс — получим `Ok(60)`;
- если не успеет — получим `Err(Elapsed)`.

## Что происходит в примере

1. `timeout` запускает `fetch_data()` и **одновременно** запускает внутренний таймер на 5 мс.
2. `fetch_data()` засыпает на 10 мс (`sleep(Duration::from_millis(10))`).
3. Через 5 мс таймер срабатывает **раньше**, чем `fetch_data` завершается.
4. `timeout` **отменяет** `fetch_data` (drop'ает future) и возвращает `Err(Elapsed)`.
5. Срабатывает ветка `Err` — печатается сообщение об ошибке.

Ожидаемый вывод:

```
Error: deadline has elapsed
```

## Ключевые моменты

### 1. `timeout` — это не отдельный поток

`timeout` **не** запускает future в фоне и **не** убивает его насильно. Он работает в том же async-контексте: опрашивает future и таймер, и как только таймер срабатывает первым — **drop'ает** future.

### 2. Отмена через `Drop`

Когда `timeout` возвращает `Err`, future `fetch_data()` **уничтожается** (вызывается его `Drop`). В данном случае это безопасно: `sleep` — cancel-safe, при drop'е таймер просто отменяется .

### 3. Cancel Safety

`timeout` безопасен **только если future cancel-safe**. Если future в момент отмены держит незавершённое действие (например, отправку в канал), данные могут потеряться. В этом примере `sleep` cancel-safe, поэтому всё корректно.

### 4. `Elapsed` — тип ошибки

`Err(Elapsed)` — это специальный тип из `tokio::time`, который означает «время истекло». Он реализует `Display`, поэтому `{err}` печатает `deadline has elapsed` .

### 5. Аналог с `select!`

`timeout(d, f)` — это синтаксический сахар над:

```rust
tokio::select! {
    res = f => Ok(res),
    _ = sleep(d) => Err(Elapsed::new()),
}
```

Но `timeout` удобнее и читаемее, когда нужно именно ограничение по времени, а не гонка нескольких future.

## Что если увеличить лимит

Если заменить `Duration::from_millis(5)` на `Duration::from_millis(50)`:

```rust
timeout(Duration::from_millis(50), fetch_data()).await
```

Тогда `fetch_data()` (10 мс) успеет завершиться **до** истечения таймера, и вывод будет:

```
Result: 60
```

## Сводная таблица

| Ситуация | Результат | Что происходит с future |
|---|---|---|
| Future завершился раньше таймера | `Ok(value)` | Future завершён нормально |
| Таймер сработал раньше future | `Err(Elapsed)` | Future **drop'нут** (отменён) |
| Future паникует | Panic | Паника распространяется |
| Future cancel-safe | — | Отмена безопасна |
| Future **не** cancel-safe | — | Возможна потеря данных |

## Итог

`tokio::time::timeout` — это простой и идиоматичный способ ограничить время выполнения асинхронной операции. Он:

- **не** создаёт отдельный поток;
- **не** убивает future насильно, а **drop'ает** его;
- требует, чтобы future был **cancel-safe**, иначе возможна потеря данных;
- возвращает `Ok(value)` при успехе и `Err(Elapsed)` при истечении времени.

В вашем примере `fetch_data()` спит 10 мс, а лимит — 5 мс, поэтому срабатывает ветка `Err` и печатается `Error: deadline has elapsed`.
